# 02 · 表字段映射矩阵

> 需求取数路径 ↔ 实际库表 ↔ 关键字段 ↔ 是否满足需求 ↔ 证据出处
> 所有表名、字段名、枚举值、行数均来自 2026-09-09 本次实跑查询。证据出处指向 `04_evidence.sql` 的对应段落。
> 行数一律为 `TABLE_ROWS`（InnoDB 估算值）或本次 `COUNT(*)` 实测值，已在表中标注哪一种。

## 0. 总览：三个实例，八张关键表

```
需求菜单（iAdmin 前端）
        │
        ├── Working Hours ────────► aws-luckyus-opempefficiency-rw / luckyus_opempefficiency
        │      Attendance Record        t_attendance（日粒度） + t_attendance_shift（班次粒度）
        │      Clocking Record          t_clock_in
        │      Employee Statistics      t_emp_scheduling（真正的排班明细）+ t_employee（门店员工）
        │      No Clocking Record  ──┐
        │                            │
        ├── Store ───────────────────┼──► aws-luckyus-opshop-rw / luckyus_opshop
        │      Forced Closure Record │      t_shop_focus_operation_log（闭店起止 + 时长）
        │                            └──► t_nobody_focus_closed_log（无人打卡预警/强闭）
        │      （需求未给路径）营业时间     t_shop_opening_time（按日）+ t_shop_opening_plan（按星期）
        │      门店主数据                  t_shop_info
        │
        └── 员工 / 岗位 / 请假 ─────► aws-luckyus-iehr-rw / luckyus_iehr
               t_ehr_employee, t_ehr_post, t_ehr_employee_post_relation,
               t_ehr_employee_leave_application (+ _day_detail, _type)
```

### 1.1 Operations System → Working Hours → **Attendance Record**（含 Attendance Status = Exception）

| 项 | 内容 |
|---|---|
| **实际库表** | `luckyus_opempefficiency.t_attendance`（表注释「考勤表」，42,145 行估算 / LKUS 41,798 行实测）<br>`luckyus_opempefficiency.t_attendance_shift`（表注释「考勤班次记录表」，41,536 行估算 / LKUS 42,234 行实测） |
| **选型依据** | 两张表是**日粒度 vs 班次粒度**的关系，不是候选二选一，**两张都要用**。`t_attendance` 的唯一键是 `(emp_no, attendance_date, scheduling_dept_id, type)`；`t_attendance_shift` 通过 `attendance_id` 挂在前者下，且额外带 `except_type_list`（多异常列表）和 `clock_in_ids`（关联的打卡记录 id 串）。一人一天两个班次时，`t_attendance` 只有 1 行、`t_attendance_shift` 有 2 行——**异常按条计数必须走 shift 表**。 |
| **关键字段** | `emp_no`、`attendance_date`(date, 门店本地日)、`type`(班次类型 1考勤/3会议/4培训/5请假/6其他/9训练)、`scheduling_dept_id`、`clock_in_dept_id`、`dept_id`(员工所属门店)、`scheduling_period`(排班时段字符串)、`rest_period`、`scheduling_hours`、`clock_in_period`(打卡时段字符串)、`effective_hours`、**`attendance_status`(0异常/1正常)**、**`except_type`(1迟到早退/2旷工/3漏打卡/4未排班打卡)**、`except_type_list`(逗号分隔多异常)、`property`(FT/PT快照)、`post_code`、`scheduling_dept_operation_area`、`clock_in_dept_operation_area`、`attendance_change_id`、`create_time`、`modify_time` |
| **是否满足需求** | ⚠️ **部分满足**。异常判定结果已存在，但**只有 4 类**，需求要的 6 类中 Late Arrival 与 Early Departure 被合并进 `except_type=1`，Missing Clock-In 与 Missing Clock-Out 被合并进 `except_type=3`。**无异常时长字段**。详见 F-02。 |
| **证据** | `04_evidence.sql` → SCHEMA 段、F-02 段 |
