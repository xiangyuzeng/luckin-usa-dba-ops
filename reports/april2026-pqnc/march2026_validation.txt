Calibration findings
--------------------
1. tenant='LKUS' is required: the table contains 7 IQA2 rows from another
   tenant that would otherwise inflate counts.

2. status IN (4,5) is the filter that distinguishes the deck's "reported
   PQNC" from raw inbox. status=4 = 待确认 (pending acceptance by responsible
   party), status=5 = 已完成 (closed). status 1/2/3 = pre-judgment states
   that the deck excludes.

3. responsibility column has an undocumented value 6 (the COLUMN_COMMENT
   only lists 1-5). In March's data, 1 row has responsibility=6 and that
   row maps to the deck's "Unknown/reject" bucket. Treating
   responsibility NOT IN (1,2,3) → Unknown/reject is the correct mapping.

4. operate_detail 1:N inflation: a small fraction of pqnc_ids have multiple
   operate_type=1 rows (re-judgments). Deduping with MIN(one_pqnc_type_code)
   over operate_type=1 gives one type per pqnc_id and reproduces canonical
   counts. (For March, only 2 pqnc_ids — 852 and 853 — had this issue;
   both had identical code 0004 across re-judgments, so MIN is safe.)
